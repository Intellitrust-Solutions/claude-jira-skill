# Jira 狀態機參考

## 典型 Atlassian Jira 工作流（本 skill 預設）

```
┌──────────┐  start work (2)   ┌────────┐  Ready (3)  ┌──────────┐
│ 待辦事項  │ ────────────────▶ │ 進行中 │ ─────────▶ │ 可供審查 │
└──────────┘                    └────────┘             └──────────┘
      ▲                            ▲ ▲                      │
      │ back (14)                  │ │ back (11)             │ UAT (5)
      │                            │ │                      ▼
      │                            │ │                    ┌─────┐
      │                            │ │                    │ UAT │
      │                            │ │                    └─────┘
      │                            │ │                      │
      │                            │ │                      │ Release (4)
      │                            │ │                      ▼
      │                            │ │                   ┌──────┐
      └────────────────────────────┼─┴─── back (14)───── │ 完成 │
                                   │                     └──────┘
                                   └── 其他 (CANCEL / Pending 等)
```

## 原則：**ID 不能寫死**

| 原因 | 對策 |
|------|------|
| Transition ID 依每個 Jira 專案的 workflow 而異 | 每次操作前動態 `GET /rest/api/3/issue/{key}/transitions` |
| 同一 issue 在不同狀態時可用的 transitions 不同 | 每步驟都重新查 |
| 專案 admin 可能改名或新增狀態 | 依名稱比對，別依 id |

## 常見 ID（SleepingBeauty 專案）

僅供參考，**實際請查**：

| Transition | ID | 去向 |
|-----------|-----|------|
| start work | 2 | 進行中 |
| Ready | 3 | 可供審查 |
| UAT | 5 | UAT |
| Release | 4 | 完成 |
| back（可供審查→） | 11 | 進行中 |
| back（完成→） | 14 | 待辦事項 |
| CANCEL | 10 | CANCEL |
| Pending | 7 | Pending |

## Test-before-Done 規則

| 當前狀態 | 代表意義 | 下一步條件 |
|---------|---------|-----------|
| 待辦事項 | 尚未開始 | 開工時推「進行中」 |
| 進行中 | 開發中或測試中 | 代碼整合完 → 推「可供審查」 |
| **可供審查** | **代碼完成，等測試** | **必須有測試證據才推 UAT → 完成** |
| UAT | 測試中 | 通過後推「完成」 |
| 完成 | 已驗證可用 | ⚠ 只有確定功能正確才能到此 |

## 批次狀態轉換注意事項

1. 失敗立刻停，不繼續推進錯誤狀態
2. 結果寫 `/tmp/jira_transition_result.json`
3. 每次 API 間隔 ≥ 0.04s 避免被限速
4. 中文 payload 必用 `ensure_ascii=True`
